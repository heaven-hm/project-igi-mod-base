# Project I.G.I. real mod menus

`demos/heaven/` is the production gameplay menu: `igi_heaven_mod_menu` builds the retail-QVM internal menu and `igi_heaven_mod_menu_external` builds the Direct3D 7 ImGui menu. Both are Windows x86 DLLs and share the same native-backed actions. Build outputs remain in `build-win32-release/`; repository `binaries/` is intentionally unused.

## Public helper API

All public helpers live in `demos/helpers/menu_helpers.hpp`, with their only implementation in `demos/helpers/menu_helpers.cpp`. Construct a helper with the `igi::Runtime` passed to a game-frame/menu callback. A helper returns `false` or `std::nullopt` when it is not executing on the live game callback thread, the game is inactive, or a required retail object is unavailable. Do not call these methods from a DLL worker thread.

- **EntityHelpers**: EntityHelpers traverses the active task hierarchy to discover live humans, cars, tanks, and helicopters using registered engine type IDs. It generates validated LiveTarget lists with stable IDs and executes safe coordinate translation, bone yaw rotations, ground attachment, and collision toggling on the verified game thread.
- **PlayerHelpers**: PlayerHelpers inspects the local human player for movement scale, stance, team, index, and health states through retail natives. It safely dispatches validated action triggers, manipulates internal controller flags, restores visual hit feedback, manages ground probing, and resets total damage across all bodily hit zones on active players.
- **WeaponHelpers**: WeaponHelpers resolves retail weapon symbols to equip firearms, binoculars, or medipacks with exact ammunition counts, toggles unlimited ammo, cycles inventory slots, and triggers draw animations. It also reads weapon ammunition counters, inspects weapon task structures, and returns verified internal event identifiers for game-thread weapon handling.
- **CameraHelpers**: CameraHelpers switches between first-person and third-person perspectives through retail Human_ViewCam and queries live camera orientation and field of view. It manipulates HumanView eye matrices, targets, and zoom factors, and renders native third-person crosshair reticles directly through the retail HUD status sprite drawing pipeline on end-frame callbacks.
- **WorldHelpers**: WorldHelpers manages mission selection across all fourteen campaign levels and executes clean level restarts through native game lifecycles. It dynamically parents rain or snow effects under the active level, manages game pause states, sets high-refresh frame caps up to 240 FPS, and reports real-time flow performance diagnostics.
- **VehicleHelpers**: VehicleHelpers targets active cars, tanks, and helicopters by task ID to read telemetry, mounted weaponry, and control parameters. It dispatches direct driving physics inputs with throttle and brakes, triggers car resets or detonations, performs level-wide fleet resets, and restores helicopters back to initial states via native branches.
- **NpcHelpers**: NpcHelpers manages selected live non-player soldiers to query status flags, equip standard firearms, clear damage totals, and toggle physical collisions. It safely forces alerted guards back to stand state, routes death animations through soldier state machines, adjusts walk or run channels, and toggles ground attachment versus air levitation.
- **AiHelpers**: AiHelpers forwards verified retail AI script natives inside authentic script callback contexts without fabricating memory structures. It adjusts visual perception distances, vision cone alpha and gamma values, event priorities, invulnerability, alarm panel linkage, gunner IDs, and animation intervals to tune guard behavior safely across active mission scenarios.
- **AudioHelpers**: AudioHelpers configures retail sound subsystems directly on the verified game thread by adjusting clamped music and sound-effects volume levels between zero and one. It applies custom audio mixing sample rates and queries the underlying sound engine to report voice counts, subsystem readiness, and playback status for mod readouts.
- **MenuActionHelpers**: MenuActionHelpers serves as the unified native dispatch bridge routing menu selections from internal QVM and external Dear ImGui frontends into verified helpers. It refreshes live target drop-downs from active level tasks and provides standalone game-thread routines for weather changes, weapon equipping, camera toggling, and level switching.

## Menu scale

Heaven ships 50 gameplay controls across six categories (Weapons, Player, Camera, World, Vehicles, AI / NPC). Heaven Advanced adds player and selected-NPC ground state, selected-NPC movement, and selected-helicopter reset without changing the normal menu. The retail QVM `MenuFrame` can only draw a handful of rows, so `igi::menuNeedsCommandList(config)` switches the generated screen to one scrollable `ListBox` over `igi::buildMenuCommands(config)`: every action becomes one runnable entry and every list value becomes its own entry. `IGI_SDK_FillList(-1)` / `IGI_SDK_GetList(-1)` / `IGI_SDK_SetList(-1, this.nActiveID)` serve that list, and `IGI_SDK_Apply()` runs the selected entry. A control set that fits keeps the direct per-control layout. `tests/HeavenLayoutTests.cpp` fails if the shipping set drops below 30 controls, loses a category, or stops generating a complete compilable resource.

## Safe unload

Never force-eject a loaded mod DLL. Build `igi_injector` and request a coordinated unload with `IGI-Injector.exe -p <igi-pid> -i <absolute-dll-path> -e`. The DLL first removes its game-thread hooks, menu callbacks, and ImGui/QVM resources; only its own host thread then calls `FreeLibraryAndExitThread`. `run-igi-wine.sh` supports the same path with `IGI_SAFE_EJECT=true`.

## Windows x86 verification

Build and run the Windows unit executable under Wine without launching the game: `WINEPREFIX=<prefix> WINEDEBUG=-all <wine> build-win32-release/igi_sdk_tests.exe`. Then use the retail executable only through the Unicorn harness, which emulates the DLL/frame callback rather than injecting it: `IGI_EXE=<retail-igi.exe> IGI_DLL=build-win32-release/igi-heaven-mod-internal.dll python3 tools/igi_runtime_harness.py --frames 5 --lenient`. Run `--verify-menu-helpers` as a separate harness invocation to validate the weather and level-transition native sequence.
