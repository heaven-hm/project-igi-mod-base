# Project I.G.I. real mod menus

`demos/heaven/` is the production gameplay menu: `igi_heaven_mod_menu` builds the retail-QVM internal menu and `igi_heaven_mod_menu_external` builds the Direct3D 7 ImGui menu. Both are Windows x86 DLLs and share the same native-backed actions. Build outputs remain in `build-win32-release/`; repository `binaries/` is intentionally unused.

## Public helper API

All public helpers live in `demos/helpers/menu_helpers.hpp`, with their only implementation in `demos/helpers/menu_helpers.cpp`. Construct a helper with the `igi::Runtime` passed to a game-frame/menu callback. A helper returns `false` or `std::nullopt` when it is not executing on the live game callback thread, the game is inactive, or a required retail object is unavailable. Do not call these methods from a DLL worker thread.

### EntityHelpers

- **`firstHuman()` & `nextHuman()`**: `firstHuman` and `nextHuman` traverse the active level task tree to locate instantiated player and NPC tasks. They validate child pointers against registered retail human and soldier type IDs, returning sequential living instances or null pointers when reaching the end of the entity container on the live game thread.
- **`firstNpc()` & `npcAt()`**: `firstNpc` and `npcAt` retrieve non-player human entities across the active level by filtering out task pointers matching the local player. `npcAt` allows indexed slot lookups across all 4096 task IDs, ensuring mod menus can query and target specific enemy guards safely without causing memory faults during mission execution.
- **`firstCar()`, `nextCar()`, & `carAt()`**: `firstCar`, `nextCar`, and `carAt` traverse the dynamic task tree for entities matching the retail car type hash. They validate vehicle task node headers, allowing mods to iterate through all active cars and tanks in the level or inspect a specific vehicle slot by zero-based index on the game thread.
- **`firstVehicle()` & `nextVehicle()`**: `firstVehicle` and `nextVehicle` inspect tasks derived from the retail vehicle base type across the level container. They provide generic vehicle hierarchy traversal for broad inspection across cars, trains, and helicopters, while enforcing pointer safety so unsupported vehicle sub-types are not passed into specialized car controllers or state handlers.
- **`npcTargets()`, `carTargets()`, & `heliTargets()`**: `npcTargets`, `carTargets`, and `heliTargets` generate lists of active level entities paired with their retail task names and unique IDs. They dynamically refresh live targets whenever menus open, allowing players to select and control guards, vehicles, and helicopters by stable task identity rather than transient memory addresses.
- **`moveHuman()` & `setHumanYaw()`**: `moveHuman` translates a live human to target world coordinates, automatically updating engine view positions, collision volumes, and slide states simultaneously. `setHumanYaw` recalculates bone matrices and yaw orientation using the verified game native, ensuring characters rotate cleanly and maintain valid animation poses without desynchronizing internal physics structures.
- **`snapHumanToGround()` & `leaveHumanGround()`**: `snapHumanToGround` and `leaveHumanGround` manipulate the retail ground-probe attachment for player or NPC human tasks. `snapHumanToGround` aligns character vertical placement directly onto terrain contours, while `leaveHumanGround` safely detaches the entity from surface collision to enable hovering, elevation adjustment, or levitation during custom mod gameplay sequences.
- **`setHumanCollision()`**: `setHumanCollision` toggles physical collision handling for a live human entity through the verified engine native. Disabling collision allows characters to bypass obstacles or escape stuck level geometry, while re-enabling collision restores normal world boundaries, bullet hitboxes, and solid surface interactions on the verified game-frame callback thread.

### PlayerHelpers

- **`moveScale()`, `state()`, `team()`, & `index()`**: `moveScale`, `state`, `team`, and `index` query core player runtime characteristics directly from retail HumanPlayer structures. They return optional values indicating current movement speed scaling, internal state indices, faction teams, and task slots, returning empty optionals if the player is not currently active on the live game thread.
- **`isDead()`, `isCrouching()`, `isActive()`, & `isPlayer()`**: `isDead`, `isCrouching`, `isActive`, and `isPlayer` provide authoritative boolean state queries regarding the local player. They read verified flags from the player entity, distinguishing living operatives from eliminated characters, confirming active input processing, and detecting crouched locomotion without relying on external or unverified mod state caches.
- **`setInputEnabled()` & `setLookEnabled()`**: `setInputEnabled` and `setLookEnabled` lock or unlock the local human player controls through retail engine natives. Disabling them prevents unwanted player movement or camera adjustments during active mod menu navigation, while re-enabling them safely restores standard keyboard and mouse look controls upon closing the menu interface.
- **`startAction()`, `checkDeath()`, & `sendPosition()`**: `startAction` dispatches verified player action IDs into the retail controller flow, while `checkDeath` triggers immediate health evaluations to update life status. `sendPosition` forces an authoritative position sync across internal task listeners, ensuring camera systems and weapon view models align precisely with current world coordinates.
- **`reportStatus()` & `restoreVisualFeedback()`**: `reportStatus` outputs a comprehensive diagnostic log detailing local player alive states, faction IDs, and controller states. `restoreVisualFeedback` calls retail player fade natives to instantly clear lingering screen-flash damage tints and hit overlays, restoring clean visual clarity to the primary viewport after taking combat damage.
- **`resetDamage()`**: `resetDamage` invokes the retail `Human_ResetDamage` native on the active player entity. It instantly clears accumulated damage totals, extinguishes lingering damage states, and restores original defense multipliers across all individual bodily damage zones, functioning as a complete health restoration action during single-player mission gameplay.
- **`snapToGround()` & `setCollisionEnabled()`**: `snapToGround` invokes the native terrain probe routine to firmly anchor the local player onto ground geometry. `setCollisionEnabled` toggles the player physical bounding volume, enabling noclip exploration through walls when disabled or restoring standard environmental barriers and projectile hit detection when re-enabled on the game thread.
- **`setFlagD44()`, `clearFlagD44()`, `setFlagD68()`, & `clearFlagD68()`**: `setFlagD44`, `clearFlagD44`, `setFlagD68`, and `clearFlagD68` directly manipulate internal retail controller bitmasks at offsets `0xD44` and `0xD68`. These low-level methods allow specialized mods to toggle internal engine movement flags, animation overrides, and player behavior states safely on the verified game callback thread.

### WeaponHelpers

- **`pickup()` & `enableUnlimitedAmmo()`**: `pickup` resolves verified retail weapon symbol constants, safely instantiating and placing firearms, binoculars, or medipacks directly into the player inventory with specified ammunition counts. `enableUnlimitedAmmo` invokes the retail unlimited ammunition native, preventing magazine depletion across all weapons for unrestricted firing during testing or custom gameplay.
- **`cycle()` & `selectCategory()`**: `cycle` forces the player to switch between carried weapons, processing next-weapon selection directly or feeding input edge updates to the game update path. `selectCategory` shifts between primary weapon classifications, ensuring smooth inventory switching across sidearms, submachine guns, rifles, heavy weaponry, and utility equipment.
- **`setAnimation()` & `requestAnimation()`**: `setAnimation` and `requestAnimation` command the player weapon viewmodel to execute specific skeletal animations through verified retail natives. They handle weapon draw sequences, reload cycles, and idle handling, allowing mod scripts to synchronize first-person firearm animations cleanly with active player combat actions.
- **`hasAmmo()` & `type()`**: `hasAmmo` inspects a supplied live weapon task to extract remaining clip and reserve round counts. `type` retrieves the underlying WeaponType descriptor block containing fire rates, recoil profiles, and bullet specifications, enabling accurate HUD readouts and custom weapon attribute auditing directly from game memory.
- **`reportFlashReset()` & `reportEvents()`**: `reportFlashReset` clears weapon muzzle flash and hit screen overlays through the player visual fade pipeline. `reportEvents` queries and logs current weapon event identifiers, allowing developers to inspect active firing, reloading, triggering, and state transitions occurring within the retail weapon execution system.
- **`fireEvent()`, `typeEvent()`, `triggerEvent()`, `stateEvent()`, & `moveEvent()`**: `fireEvent`, `typeEvent`, `triggerEvent`, `stateEvent`, and `moveEvent` return internal weapon event identifiers registered in the retail task system. These constants allow advanced mod routines to intercept, broadcast, or handle custom weapon firing sequences, trigger pulls, weapon transitions, and viewmodel movement events safely on the game thread.

### CameraHelpers

- **`setViewMode()`, `mode()`, & `isThirdPersonActive()`**: `setViewMode` invokes retail `Human_ViewCam` with mode one for first-person or mode two for third-person perspective. `mode` retrieves the effective active camera setting from the retail camera-info handler, while `isThirdPersonActive` returns true strictly when verified third-person rendering is currently active in the running game.
- **`reportInfo()`**: `reportInfo` queries the retail camera-info handler to publish a live diagnostic readout of current viewing parameters. It logs the active camera mode, horizontal and vertical field of view angles, and exact world-space eye coordinates, verifying that viewport matrices correspond with authentic game state.
- **`setWeaponTarget()` & `setWeaponAngles()`**: `setWeaponTarget` and `setWeaponAngles` adjust pitch and yaw orientation angles on a supplied live HumanView structure. They allow mod scripts to control where carried weapons point, modifying aiming elevations and tracking speeds smoothly without corrupting underlying player skeletal matrices on active game frames.
- **`setCamera()`, `setTarget()`, `setDip()`, & `setZoomed()`**: `setCamera`, `setTarget`, `setDip`, and `setZoomed` manipulate view matrix positioning, camera target anchors, vertical dip offsets, and scope magnification levels on a supplied HumanView. They enable custom cinematic camera sequences, dynamic scope zoom adjustments, and stabilized viewpoint tracking during custom gameplay events.
- **`eye()`, `forward()`, & `matrix()`**: `eye`, `forward`, and `matrix` read raw viewpoint telemetry from an active HumanView instance into caller-provided memory. `eye` extracts exact camera world coordinates, `forward` calculates normalized directional viewing vectors, and `matrix` populates complete three-by-three rotation matrices for custom math, projectile spawning, and spatial raycasting.
- **`setThirdPersonCrosshairEnabled()` & `renderThirdPersonCrosshair()`**: `setThirdPersonCrosshairEnabled` configures whether the third-person aiming reticle should render on screen. `renderThirdPersonCrosshair` queries player camera mode, active weapon sights, and display resolution on game end-frame callbacks, drawing centered crosshair reticles via the retail HUD sprite pipeline strictly during third-person aiming.

### WorldHelpers

- **`changeLevel()` & `restartMission()`**: `changeLevel` selects retail campaign missions from one to fourteen, coordinating menu resource detachment and game task destruction before loading the chosen level. `restartMission` executes the native level reload sequence, resetting the current mission cleanly without requiring a return to the main menu.
- **`setWeather()`**: `setWeather` manages environmental precipitation by parenting retail RainEffect tasks under the active Level. Passing Rain or Snow dynamically discovers and recreates weather nodes with proper event broadcasts, while passing Off deletes all existing precipitation tasks to restore clear environmental conditions on the live game thread.
- **`setPaused()` & `isPaused()`**: `setPaused` freezes or unfreezes global simulation updates through the retail game pause native, allowing mods to decouple menu display from game state. `isPaused` queries the internal engine pause flag, returning true when mission execution, enemy AI, and timers are currently suspended.
- **`refreshDisplay()` & `setFrameCap()`**: `refreshDisplay` triggers a DirectX display mode reapplication to correct rendering anomalies or window dimension changes. `setFrameCap` invokes retail timing natives to enforce frame limits including 30, 60, 120, 144, or 240 FPS, smoothing camera motion and eliminating physics jitter on modern high-refresh monitors.
- **`reportLevelTick()`, `reportFlow()`, & `reportEvents()`**: `reportLevelTick` logs the current level simulation tick count, `reportFlow` publishes real-time frame rates and render counters, and `reportEvents` logs engine lifecycle event status. These helpers provide immediate insight into engine simulation cadence, verifying that background frame loops run at stable rates.
- **`event()`, `flowFps()`, `flowFrames()`, `flowRenders()`, `taskCount()`, & `logFlowDiagnostics()`**: These methods extract individual engine performance counters from verified flow and level structures. They return frame-rate averages, total elapsed frames, active render passes, and current task allocation counts, outputting complete telemetry summaries via `logFlowDiagnostics` for in-depth mod performance profiling.

### VehicleHelpers

- **`carControlInfo()`, `carFrame()`, `carLight()`, & `carTrackFactor()`**: `carControlInfo` extracts steering and acceleration parameters from a supplied live Car entity, while `carFrame` retrieves transformation matrices. `carLight` queries headlight illumination states, and `carTrackFactor` inspects tread animation scaling on tracked armored vehicles, providing accurate telemetry readouts for ground vehicles.
- **`carMountedGun()` & `carGunnerPose()`**: `carMountedGun` locates weapon tasks installed on armored vehicles and trucks, returning valid pointers to vehicle turrets. `carGunnerPose` calculates world-space coordinates and orientation matrices for manned gunners, ensuring mounted weapon controls align correctly with vehicle movement during active combat missions.
- **`driveCar()`, `resetCar()`, & `resetControls()`**: `driveCar` dispatches normalized throttle and braking values into the retail car physics controller, enabling automated or scripted vehicle driving. `resetCar` restores upright orientation and clears velocity on stuck vehicles, while `resetControls` resets steering and throttle inputs back to neutral resting state.
- **`explodeCar()`, `explodeAllCars()`, & `resetAllCars()`**: `explodeCar` detonates a targeted Car entity using the retail explosion native, spawning blast effects and eliminating occupants. `explodeAllCars` and `resetAllCars` iterate across all active vehicle tasks on the map, allowing mod menus to detonate or reset every ground vehicle simultaneously with a single command.
- **`resetHeli()` & `resetVehicleControls()`**: `resetHeli` invokes the retail tick zero control branch on an active helicopter task, resetting rotor speeds, flight parameters, and AI navigation back to initial setup. `resetVehicleControls` invokes the catalogued vehicle reset handler on generic vehicle tasks to clear temporary control states safely.
- **`reportCarInfo()`, `reportHeliInfo()`, & `heliDoor()`**: `reportCarInfo` and `reportHeliInfo` format and publish detailed telemetry logs for cars, tanks, and helicopters, detailing control inputs and mounted weapons. `heliDoor` queries access hatch states on helicopters, verifying whether side doors are open for passenger entry and exit.
- **`heliControlInfo()`, `heliStateSize()`, `heliConfigSize()`, & `heliSoundInfo()`**: These helpers query internal helicopter subsystem properties directly from game memory. They retrieve control telemetry blocks, state machine memory sizes, configuration buffer requirements, and audio parameters, allowing advanced vehicle scripts to monitor and manipulate helicopter tasks without causing structure overruns.

### NpcHelpers

- **`ensureWeapon()`**: `ensureWeapon` invokes the retail soldier weapon creation routine for a selected live NPC. It instantiates appropriate firearm tasks matching the guard unit type and attaches them into the character hand bones, arming unarmed enemies or restoring weapons to guards during custom scenario setups.
- **`resetDamage()`**: `resetDamage` executes the retail damage reset native against a selected non-player soldier. It clears all accumulated injury values, extinguishes active wound states, and restores standard damage reduction multipliers across head, torso, and limb hitboxes, completely healing the targeted guard on the game thread.
- **`snapToGround()` & `setCollisionEnabled()`**: `snapToGround` probes terrain height beneath a targeted NPC, snapping the soldier feet directly onto ground contours to fix geometry clipping. `setCollisionEnabled` toggles physical collision meshes, allowing guards to pass through walls or restoring solid world barriers and bullet vulnerability.
- **`standDownSoldier()` & `executeSoldier()`**: `standDownSoldier` returns an alerted enemy soldier back to calm standing posture via `Soldier_StandEnter`, extinguishing alarm responses. `executeSoldier` triggers the retail death state-machine transition using verified state pointers, eliminating the targeted guard instantly with authentic ragdoll animations and sound effects.
- **`reportStatus()` & `reportSoldierParams()`**: `reportStatus` queries and logs team affiliations, current state indices, and alive flags for a targeted NPC. `reportSoldierParams` extracts the internal soldier parameter block, exposing view distances, weapon accuracy, and reaction coefficients for real-time AI tuning and behavioral auditing.
- **`setMovementMode()` & `clearMovement()`**: `setMovementMode` configures whether a targeted NPC utilizes walking or running movement channels within their AI navigation controller. `clearMovement` halts active patrol routes and cancels current pathfinding objectives, stopping the soldier in place until new movement commands are assigned by the game.

### AiHelpers

- **`removeAlarmActions()`**: `removeAlarmActions` clears queued alarm responses from the active AI controller within an authentic script callback context. It prevents alerted guards from sprinting toward alarm panels or sounding sirens, neutralizing base-wide alert escalations during stealth missions without altering core patrol behaviors.
- **`setViewLength()`, `setAlarmViewLength()`, `setViewAlpha()`, & `setViewGamma()`**: These helpers configure primary vision cone parameters for enemy AI units. They adjust visual detection distances and angular vision widths under both standard patrol and heightened alarm states, allowing modders to customize guard sightlines, peripheral awareness, and stealth detection sensitivity.
- **`setSecondaryViewLength()`, `setSecondaryAlarmViewLength()`, `setSecondaryViewAlpha()`, & `setSecondaryViewGamma()`**: These methods calibrate secondary sensory perception zones for enemy soldiers. They fine-tune long-range peripheral detection, ambient awareness, and heightened sensory thresholds when bases enter alert status, enabling complex layered detection cones for realistic stealth gameplay balance across custom missions.
- **`setEventPriority()`, `setInvulnerability()`, `setInstantDeath()`, & `setDeathAnimation()`**: These helpers configure AI event handling priorities, toggle temporary damage immunity, enforce instant lethal vulnerability, and assign custom death animation indices. They provide fine-grained control over how soldiers react to stimuli, take damage, and collapse upon defeat in scripted combat sequences.
- **`setAlarmTriggerId()`, `setAlarmControlId()`, & `setAlarmAccess()`**: These methods link AI units with specific alarm panel task IDs, control switches, and authorization levels. They govern which alarm stations guards interact with during base alarms, redirecting reinforcement calls or locking down specific security terminals across the active military base.
- **`setGunnerId()` & `setAnimationInterval()`**: `setGunnerId` assigns an AI soldier task to operate fixed machine gun emplacements or vehicle turrets. `setAnimationInterval` specifies frame delays between behavioral animation updates, allowing scripts to adjust the frequency of guard idle gestures, fidgets, and patrol scanning animations.
- **`currentEventType()` & `randomValue()`**: `currentEventType` retrieves the internal event type code currently being evaluated by the AI state engine. `randomValue` extracts deterministic pseudo-random numbers generated by the script context, ensuring procedural patrol variations, glance timings, and reaction delays remain reproducible and synchronized across engine ticks.

### AudioHelpers & Standalone Action Helpers

- **`setMusicVolume()` & `setSfxVolume()`**: `setMusicVolume` and `setSfxVolume` clamp user input values between 0.0 and 1.0, forwarding them directly into retail audio mixing natives on the game thread. They provide smooth, real-time volume adjustment for background music tracks and tactical sound effects across the game.
- **`setRate()` & `reportInfo()`**: `setRate` adjusts the master audio mixing sample rate within the underlying sound engine to optimize playback performance. `reportInfo` queries the active sound subsystem to log driver initialization status, current sample rates, and total active audio voice counts for diagnostic verification.
- **`executeMenuNativeAction()` & `refreshLiveTargetOptions()`**: `executeMenuNativeAction` serves as the central game-thread dispatcher routing internal QVM and external ImGui menu selections directly into verified helper methods. `refreshLiveTargetOptions` scans the dynamic task table periodically to populate target drop-down lists with newly spawned level entities.

## Menu scale

Heaven ships 73 gameplay controls across eight categories (Weapons, Player, Human, Camera, World, Vehicles, AI / NPC, System). The Human section reads the live humanplayer.qvm jump speed and jump height globals, applies typed values from the two input boxes on Save, and restores the authored values with HumanPlayer_LoadParameters. The Vehicle section adds helicopter stop/drive (Heli_Control) and tank drive (Car_Control). Heaven Advanced adds player and selected-NPC ground state and selected-NPC movement without changing the normal menu. The retail QVM `MenuFrame` can only draw a handful of rows, so `igi::menuNeedsCommandList(config)` switches the generated screen to one scrollable `ListBox` over `igi::buildMenuCommands(config)`: every action becomes one runnable entry and every list value becomes its own entry. `IGI_SDK_FillList(-1)` / `IGI_SDK_GetList(-1)` / `IGI_SDK_SetList(-1, this.nActiveID)` serve that list, and `IGI_SDK_Apply()` runs the selected entry. A control set that fits keeps the direct per-control layout. `tests/HeavenLayoutTests.cpp` fails if the shipping set drops below 30 controls, loses a category, or stops generating a complete compilable resource.

## Safe unload

Never force-eject a loaded mod DLL. Build `igi_injector` and request a coordinated unload with `IGI-Injector.exe -p <igi-pid> -i <absolute-dll-path> -e`. The DLL first removes its game-thread hooks, menu callbacks, and ImGui/QVM resources; only its own host thread then calls `FreeLibraryAndExitThread`. `run-igi-wine.sh` supports the same path with `IGI_SAFE_EJECT=true`.

## Windows x86 verification

Build and run the Windows unit executable under Wine without launching the game: `WINEPREFIX=<prefix> WINEDEBUG=-all <wine> build-win32-release/igi_sdk_tests.exe`. Then use the retail executable only through the Unicorn harness, which emulates the DLL/frame callback rather than injecting it: `IGI_EXE=<retail-igi.exe> IGI_DLL=build-win32-release/igi-heaven-mod-internal.dll python3 tools/igi_runtime_harness.py --frames 5 --lenient`. Run `--verify-menu-helpers` as a separate harness invocation to validate the weather and level-transition native sequence.
